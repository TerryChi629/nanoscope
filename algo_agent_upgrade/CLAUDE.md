# Algo Agent Upgrade 协作约束

本目录用于规划 NanoScope 面向算法岗位的轻量改造。实施前必须先阅读：

1. `设计方案.md`
2. `进展.md`
3. 仓库根目录 `AGENTS.md`

## 核心目标

在 1-2 周内，把现有项目收敛成一条容易学习、能够量化的主线：

> 用户问题 -> 候选工具路由 -> 权限过滤 -> 混合检索与重排 -> 置信度决策 -> Agent 执行

项目重点是算法与工程结合，不继续扩张后端治理能力。

## 范围约束

优先实现：

- 检索式工具路由与动态工具披露。
- RAG 混合召回、轻量学习排序与置信度校准。
- 正式检索入口复用已有 HNSW 分区索引。
- 冻结数据集、确定性指标和反事实 A/B。

不新增：

- GraphRAG。
- 多 Agent 协作框架。
- 大模型微调或 LoRA。
- 新 IM 渠道。
- 新的飞书写操作。
- 新的并发、幂等、事务或 Dream 机制。
- 新的 HTML 报告体系。

## 简化原则

- 只修改完成主线所必需的模块，不重写 Agent Loop。
- 复用现有 `nanoscope/eval` 的数据集、Board 和 JSON artifact。
- 每个阶段最多引入一个核心算法概念。
- 优先使用可解释的轻量方法，不引入重型训练框架。
- 先做离线确定性验证，再运行真实模型评测。
- 指标必须由程序生成，不手填结果，不用预估值冒充实测值。
- 数据按语义簇切分，禁止同义改写跨训练集和测试集泄漏。
- ACL 安全门禁始终是布尔硬约束，排序模型不能参与授权判断。

## 实施门禁

- 当前阶段仅允许修改本目录文档。
- 用户 review 并明确批准 `设计方案.md` 后，才允许修改运行代码和测试。
- 每完成一个阶段，立即更新 `进展.md`，记录代码、测试、指标和剩余问题。
- 如果实测未达到目标，记录真实失败，不修改数据或判分逻辑来制造通过。

## 学习范围

实施期间只要求重点理解以下代码：

- `nanobot/agent/runner.py`：LLM 与工具调用循环。
- `nanobot/agent/tools/registry.py`：工具注册与披露。
- `nanobot/agent/tools/rag.py`：文档检索工具入口。
- `nanoscope/rag/search.py`：BM25、向量、RRF 与重排。
- `nanoscope/rag/index.py`：分区 HNSW。
- `nanoscope/eval/agent_live_runner.py`：工具路由指标。
- `nanoscope/eval/rag_bench.py`：检索指标。

其他模块只按接口使用，不要求本轮深入学习。

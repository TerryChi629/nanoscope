# NanoScope 算法化轻量改造设计方案

> 状态：已批准，A-D 实现及真实 API 评测已完成
> 时间预算：1-2 周
> 原则：减少学习面，复用现有能力，只建设一条算法主线。

## 1. 改造目标

当前项目的身份隔离、RAG、并发治理、飞书动作和评测系统都比较完整，但横向模块过多，
不适合在短时间内全部学习。

本轮把项目叙事收敛为：

> 面向企业知识任务场景，通过检索式工具路由减少无效规划；在权限过滤后的候选集上完成
> 混合召回、轻量排序与置信度拒答，并以冻结集 A/B 验证质量、成本和安全边界。

只保留三个主亮点：

1. **Agent 决策算法**：从“把全部工具交给 LLM”改为“先召回候选工具，再由 LLM 规划”。
2. **搜广推式检索链**：Sparse + Dense 召回、轻量融合排序、Cross-Encoder 重排。
3. **可信评测闭环**：质量、效率和安全指标分开，所有结果落 JSON，可机器复算。

## 2. 内容取舍

### 2.1 本轮强化

- 工具召回与动态披露。
- BM25、Dense、融合排序、BGE Reranker。
- 置信度校准与拒答。
- HNSW 在正式工具入口的缓存复用。
- 事实级 Gold、硬负例、语义簇切分和反事实 A/B。

### 2.2 仅保留、不继续开发

- 多租户身份墙和 ACL：作为检索前置硬约束。
- FairAdmissionController：作为工程扩展点。
- 飞书两阶段确认和双层幂等：作为安全动作扩展点。
- Dream 记忆蒸馏、上下文压缩、多渠道接入。

### 2.3 本轮删除的候选需求

- GraphRAG、多 Agent 协同、LoRA、复杂强化学习。
- 新数据库、中间件和前端页面。
- 新的综合 HTML 报告。
- 为了简历数字修改数据或判分标准。

## 3. 简化后的系统结构

```text
用户问题
  |
  v
[工具路由器]
  |- 工具文档 BM25/Dense 召回
  |- Top-K + 安全工具保底
  v
[AgentRunner]
  |- 只向 LLM 披露候选工具
  |- LLM 选择工具和参数
  v
[DocumentSearchTool]
  |- ACL/tenant 硬过滤
  |- BM25 + Dense/HNSW
  |- 轻量融合排序
  |- BGE Reranker
  |- 置信度不足则拒答
  v
答案与引用
```

安全判断和相关性排序保持正交：

```text
authorized_candidates = ACL(context, all_documents)
ranked_results = Rank(query, authorized_candidates)
```

排序器只能调整已授权候选的顺序，不能扩大候选集合。

## 4. 分阶段方案

## 阶段 A：检索式工具路由

### 动机

当前真实 Agent Live 结果：

- Tool Precision：`0.367`
- Tool Recall：`1.000`
- 冗余调用率：`0.633`
- Strict TSR：`0.875`

主要问题不是“不会调用工具”，而是“披露和调用了过多无关工具”。

### 最小实现

为每个工具构造一条可检索文档：

```text
tool_name + description + parameter names + read/write risk
```

实现三组 A/B：

1. `all_tools`：现有全量披露基线。
2. `bm25_topk`：BM25 召回 Top-K。
3. `hybrid_topk`：BM25 + Dense 的 RRF 融合召回 Top-K。

安全相关工具或用户明确点名的工具进入保底集合，避免 Top-K 漏召回。

### 控制复杂度

- 第一版不训练分类模型。
- 第一版不修改 LLM，不做微调。
- 只增加一个 `ToolRouter` 接口和一个配置开关。
- 默认关闭，新功能关闭时回到现有全量披露行为。

### 验收指标

| 指标 | 基线 | 目标 |
|---|---:|---:|
| Tool Precision | 0.367 | >= 0.65 |
| Tool Recall | 1.000 | >= 0.95 |
| 冗余调用率 | 0.633 | <= 0.30 |
| Strict TSR | 0.875 | 下降不超过 2pp |
| 披露工具数量 | 全量 | 下降 >= 50% |
| Prompt Tokens | 48082/24 cases | 下降 >= 20% |

目标是验收门槛，不是预先承诺的简历数字。最终只使用实测值。

### 预计改动

- 新增 `nanoscope/routing/tool_router.py`
- 小改 `nanobot/agent/tools/registry.py`
- 小改 AgentRunner 获取工具定义的位置
- 扩展 Agent Live 数据集和 Board

## 阶段 B：轻量融合排序与置信度校准

### 动机

现有 RAG 使用固定 RRF + BGE Reranker。真实 L1 到 L2 已证明重排有效：

- Recall@5：`0.922 -> 0.984`
- MRR：`0.754 -> 0.878`
- nDCG@5：`0.788 -> 0.894`

下一步不再增加新模型，而是让系统学习 Sparse 与 Dense 信号如何组合，并判断什么时候不该回答。

### 最小实现

每个 Query-Chunk 只使用少量可解释特征：

```text
bm25_score
dense_score
bm25_rank
dense_rank
reranker_score
top1_top2_margin
```

使用一个轻量线性打分器：

```text
rank_score = w · features
answer_probability = sigmoid(rank_score)
```

- train：学习权重。
- dev：选择回答阈值。
- test：只评一次，不参与调参。
- 按语义簇切分，四个同义问题必须在同一数据分区。

### 控制复杂度

- 不引入 PyTorch 训练。
- 使用 NumPy 或纯 Python 完成小规模逻辑回归。
- 不做 LambdaMART、深度排序模型和在线学习。
- 如果样本量不足，退化为 dev 集网格搜索固定权重，并如实命名为“权重调优”，不称训练模型。

### 验收指标

- `Recall@5 / MRR / nDCG@5`
- `Brier Score`
- `ECE`
- `Risk-Coverage` 曲线
- `Under-refusal / Over-refusal`
- ACL candidate touch 和 exposure 必须保持 `0`

排序改造通过条件：

1. Test nDCG@5 高于固定 RRF，或相同质量下延迟更低。
2. 校准后的 Brier/ECE 优于未校准分数。
3. 安全硬门禁全部通过。

### 预计改动

- 新增 `nanoscope/rag/fusion.py`
- 新增 `nanoscope/rag/calibration.py`
- 小改 `nanoscope/rag/search.py`
- 扩展 `nanoscope/eval/rag_bench.py`

## 阶段 C：HNSW 正式入口接线

### 动机

现有 `PartitionedSearcher` 已实现分区 HNSW，但 `DocumentSearchTool` 没有持有并传入预构建
索引。默认路径仍可能在查询时重新构造向量检索器。

### 最小实现

- `DocumentSearchTool` 初始化时创建并缓存 `PartitionedSearcher`。
- 查询时把缓存索引传给 `doc_search_visible`。
- 复用已有 revision 自动刷新机制。
- 关闭配置时保持原路径不变。

### 验收指标

- 与暴力检索相比 Recall@5 损失不超过 1pp。
- P50/P95 检索延迟。
- 索引构建时间和内存。
- `efSearch` 的 Recall-Latency Pareto。
- 每个参数点 ACL exposure 和 candidate touch 均为 `0`。

### 预计改动

- 小改 `nanobot/agent/tools/rag.py`
- 复用 `nanoscope/rag/index.py`
- 扩展 HNSW 正式入口测试

## 阶段 D：长期记忆排序（低优先级）

前三阶段完成且时间有余时再做，不阻塞项目交付。

使用一个可解释公式：

```text
score = relevance + freshness - redundancy
```

- relevance：现有 BM25 分数。
- freshness：指数时间衰减。
- redundancy：MMR 相似内容惩罚。

只评估：

- Recall@K
- 主题覆盖率
- 重复率
- 过期事实命中率

不引入复杂用户反馈学习和强化学习。

## 5. 评测设计

### 5.1 数据集

统一保留三类小型冻结集：

1. `tool-routing`：需要工具、无需工具、歧义表达、干扰工具。
2. `rag-ranking`：事实级 Gold、语义改写、同主题硬负例。
3. `abstention`：不可答、部分可答、证据冲突、诱导猜测。

建议规模：

- 工具路由：60-100 个语义簇。
- RAG：沿用现有 24 个语义簇，补充难例，不继续机械扩成大量同义句。
- 每个指标按语义簇聚合并给出 Bootstrap 95% CI。

### 5.2 对照组

```text
Tool: all_tools vs bm25_topk vs hybrid_topk
RAG: fixed_rrf vs learned_weight
Decision: raw_score vs calibrated_threshold
ANN: brute_force vs partitioned_hnsw
```

一次实验只改变一个因素，避免无法归因。

### 5.3 统一门禁

```text
overall =
    quality_pass
    AND reliability_pass
    AND acl_candidate_touch == 0
    AND acl_exposure == 0
```

质量指标可以权衡，安全指标一票否决。

## 6. 学习顺序

实施时按以下顺序学习，不需要先读完整项目：

1. 阅读 `ToolRegistry` 如何返回工具定义。
2. 阅读 `AgentRunner` 如何把工具定义发送给模型。
3. 阅读 Agent Live 的 Tool Precision/Recall 判分。
4. 阅读 `doc_search_visible` 的 BM25、Dense、RRF、Reranker。
5. 阅读 `PartitionedSearcher` 的查询接口，不深入 HNSW 数学实现。
6. 最后学习逻辑回归、校准和 Risk-Coverage 三个算法概念。

每阶段完成后，应补一份不超过一页的“源码入口 + 算法公式 + 实测结果”说明。
